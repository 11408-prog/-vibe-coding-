# -vibe-coding-
  在尝试使用claude,codex等ai制作一个用于聊天和简单办公的agent，记录一些心得和问题。由于是随便写的，因此可能观感不太好。之后可能会整理一下。目前项目的链接是
[azur_agent](https://github.com/11408-prog/azur_agent)。

## 背景
  制作该agent的动机是由于本人十分喜欢碧蓝航线中一个叫企业的角色，加上对于vibecoding感兴趣，于是决定制作该软件。使用的是Qt6,借助了ElaWidgetTools的ui框架。目前还在开发，只能胜任简单的角色对话和一些简单代码及同人文生成生成工作。

## 日志

### 2006/8/5
  由于已经进行了快一个月的开发才有写这个文档的想法，因此这次先做一些总结性的东西。因为我当时觉得ela的风格和ui很吸引我，加上有一些c++基础，因此选择了qt框架。说实话，选择一个好的框架是很重要的，可以帮忙省去很多麻烦（包括不限于解决qt原生控件难看，ai制作的页面丑陋且使用莫名其妙的风格和emoji）。开发的过程整体是比较顺利的，流程基本就是我提出要求，ai帮忙实现，之后我来进行测试。自己发现问题并且把问题描述清楚是很关键的，如果只是一味把文件丢给ai让ai发现bug并修复可能会发现一直能review出bug，而且其实有一些bug是无关紧要的。之前在网上看说claude的公司是采用重新写代码的方式解决bug，由于token需要钱而且感觉这样并不靠谱因此没有试过。<br>
  比较重要的一次事是由于当时刚好在微信公众号看到了一篇讲关于mainwindow过于臃肿的危害的文章，当时意识到了文件过大或者职责过多时需要解耦，也是我第一次了解到了单一职责原则（SRP）是什么。解耦倒是花费了比预期久的时间，因为我一开始的策略比较激进，导致解耦完就会出现问题。之后感觉不管是加内容还是减内容都需要一步一步来，不能完全交给ai，因为ai是没法对代码负责的。而且有时候ai会提出一些不太合理的建议，盲目实施的话会有项目失控的风险。<br>
  这两天在思考要不要把开发环境迁移到linux上并进行了尝试。先后尝试了Ubuntu和LinuxMint。由于我使用的是虚拟机加上电脑的性能不是很好，导致很卡（这是最不能忍受的一点，严重影响了体验）。而且这两次搭建过程让我仔细想了想是否有迁移环境的必要。得出的结论是没有，因为我的目的是制作agent，Linux在这个过程中显然不是必要的，对于我当前的开发来说其编译速度快和搭建环境容易并没有多大的优势说实话,因为使用ide(qt creator)能够完全满足需求。<br>
  还有一件值得一提的事是关于本地部署模型接入agent。当时我和同学聊天的时候他认为可以尝试在本地部署模型，这样可以省去token的费用。但是感觉这个很吃电脑的配置（也可能是因为我没找到合适的模型，我只尝试了一些通义千问和其它公司的蒸馏模型），实际使用的效果不太好，运行速度有些慢。不过确实是一个不错的选择，在要求比较低时还是可以的。<br>
  目前想到的只有这些。感觉这段时间的软件开发对于我还是很有帮助的。因为我本身并不是计算机科班的，专业是数据科学与大数据技术。这段时间的vibe coding使我感受到了ai的强大，ai的威力显然不局限于做一些作业和题，它可以干很多事情。不过在不同的人用起来效果可能天差地别，比如做一个网站，如果一个人只是单纯说一句"制作一个网站"之后反复重复美化一下，另一个人则写比较详细的提示词并能反复精准地指出不足，那这两个网站的差距可想而知（可以自己控制变量法尝试一下）。而且这段经历给我带来了很大的成就感，能和喜欢的二次元角色聊天无疑是一件很令人快乐的事，而且我个人很享受写代码的过程，有种聚沙成塔和四两拨千斤的感觉。同时也让我学到了很多，比如代码不是越多越好，有时候代码很多可能是因为逻辑重叠等问题，只能说明项目有些臃肿。<br>
  接下要做的应该就是完善功能。由于vibe出了相当多的代码，感觉确实有地方需要优化，做的不太好。对于整个项目而言,有效产出的代码应该会越来越少，但是项目肯定会越来越好。<br>

## 一些问题和解决方法

### UI / 界面

**Q: 页面中边栏的代表 .exe 的图标始终删除不了**<br>
A: 直接把整个栏隐藏即可。

### 窗口

**Q: 怎么使程序默认是全屏的**<br>
A: 将 `w.show();` 换为 `w.showMaximized();`

### Git

**Q: 怎么提交 git 项目**<br>
A:
```bash
git status                  # [1] 看状态
git diff --stat             # [2] 看改动量
git add 文件1 文件2 目录/    # [3] 暂存（用目录名代替 .）
git commit -m "说明"        # [4] 提交
```

**Q: 怎么快速提交项目**<br>
A:
在项目目录下的终端输入  
```bash
git add .; git commit -m "更新"; git push
```
### AI 模型 / Agent 配置

**Q: 使用 Ollama 下载的本地部署模型，调用时 url 输入什么**<br>
A: 输入 `http://localhost:11434/v1`

**Q: 选择支持 Claude Code 的模型要注意什么**<br>
A: 一定要能支持**工具调用**。
